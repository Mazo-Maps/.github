# Security Policy

## Reporting a vulnerability

**Do not report security vulnerabilities in public issues or discussions.**

If the affected repository has GitHub private vulnerability reporting enabled, use its **Security → Report a vulnerability** option. Otherwise, contact an organization owner privately through an established verified channel. Please do not post exploit details publicly while a report is being assessed.

Include affected components, reproduction steps, potential impact, and a suggested fix if available. Do not include live credentials or sensitive personal data.

## Scope and response

Mazo Maps maintainers will review reports as capacity permits. No fixed response or remediation time is promised. Coordinated disclosure is encouraged.

## Responsible testing

Avoid accessing other users' data, disrupting services, or testing systems without authorization.
